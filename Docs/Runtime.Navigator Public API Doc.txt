Explicit Invocation for Explicit Implementations

Publci API Doc

Runtime Navigator: Reify generic types and methods, load static types, load instances, invoke methods, fields and properties at runtime. Create variables,
pass fields, properties, the loaded instance, and variables as arguments to method parameters, or assignment. Access members of fields, properties
and variables for invocation.
All inputs are case insensitive, including values (except strings/chars), member names, and type names. 
If your code has types and members with the same name but in different cases, you will encounter
ambiguity errors when trying to locate members (the system will overwrite members that have the same caseless name and some will appear to be missing)
as well as throwing duplicate type key exceptions when caching your types.





Using the Navigator: Syntax/Basic Use

Syntax has the same rules as you see in C#, with a few restrictions.
Invoking a method and assignment looks the same as it would in normal code. IE. "MethodName(22, true, variable)" or "IntField = 15"
When a type or instance is loaded, you have implicit access to it's methods, fields and properties, and do not need to qualify them with a typename.
When you enter the name of a field, property, or variable, the value is returned, IE. "PropertyName" returns the propertys value. You can return
values directly from fields, properties and variables by simply typing the name, or pass them by name as parameters to methods/assignment.

Member access is the primary restriction. Member access must be a TypeName.MemberName pair. For fields and properties that you have implicit access to,
you can acess their members as if they were a type. IE. PropertyName.Method(). This also works for variables.
namespaces in type names ex. Namespace.Type.Member will not interfere with this feature.

You do not need to reload the current type or instance to invoke members from outside the current type or instance.
You can lead with a typename, member name, or variable name, IE. StaticType.Method() or VariableName.Field or FieldName.Method() or FieldName = StaticType.Method() etc
You can also use leading with a typename to cast the current instance without changing the loaded type, gaining explicit access to members of the casted type for that
invocation - IE. BaseType.BasePrivateField or BaseType.BasePrivateMethod(BaseType.Field) its not only for
private members but that's what it's most useful for. You can also use the typename 'base' to access the instance type's immediate base type.
Casting still follows standard C# polymorphism, even if you cast to a base type, invocations will use the instance type's overrides.

You can return the current tostring value of this by simply typing 'this', and you can pass 'this' as a parameter to methods to return the loaded instance
by value.

You can also explicitly declare accessing from the current instance using 'this', ie this.fieldname, however this is not usually necessary due to implicit access.
Note, if you have casted your instance into a base, accessing 'this' will return members from the currently loaded base type, not the instance type.

Furthermore, 

Enumerable values are automatically enumerated and printed for your viewing upon return, either from a method, field, property, or this. Variables that store
enumerable values are not read automatically when returned, they must be loaded as an instance first.

Member access is restricted for method return values. IE. You cannot do Method().Field this is restricted.

Methods with in/out/ref parameters and ref returntype are not supported. You cannot yet pass methods as arguments for delegates, but you may be able to later.

Expressions are not supported. You cannot do math, you cannot create lambda expressions, the only available expression is assignment.

Indexers are not supported. You must invoke the backing get_item() method.

You cannot pass methodgroups as parameters for delegate arguments.

Whitespace - Avoid whitespace as part of type names, variable names, member names, and in type argument parameters. Otherwise, it is safe to have them in method parameters.
They are also allowed right after the method's name.
Ex.
class<int>.method  (22  , "hello world"   , fieldname  ) GOOD

cl ass  <int, string>.met hod  (22  , "hello world", fiel dname  ) 
  ^BAD ^BAD  ^BAD        ^BAD                            ^BAD       These things will cause exceptions. I will fix generics type args later. maybe.

Additional Tips:

Default parameters are supported. Params arrays are supported.
the values 'default' and 'null' have been included.

If a field or property name conflicts with our "keywords" - null, base, this and default (caseless) - you will have problems
accessing that field or property. You can access it explicitly using typename, ex Class.this or this.this, obviously
you will lose the ability to use them in typename-membername pairs for invocation.

Enum OR is supported, but avoid placing whitespace. Send values like|this.
Strings and chars should be declared just like C#.
Again, nothing is case sensitive. Type names, field names, variable names, method names, all case insensitive.
Variables can be used in assignment. They cannot be assigned null.

Explicit Invocation For Explicit Implementations:
You will occasionally encounter explicit interface implementations, such as the backing methods for IList's indexer property in arrays.
It will have a key that is invalid and mangled looking (method keys arent allowed to have periods or typenames in them), such as this
[0] [Key: System.Collections.IList.get_Item :: private sealed instance Object Array::System.Collections.IList.get_Item(Int32 index)]
You must use casting to invoke these methods, using their cache type name.
ex. ilist.get_item(1);
or
~ ^ilist; get_item(1); (You will learn more aobut what ~ and ^ does below)

Strings have very simple escape support. \ will remove the very next character from the string, whatever it is.
Putting @ infront of a string will prevent escape.



Using the Navigator: Controllers

Use controllers to invoke specific operations that interface with the Navigator.
Controllers are one character long and must be placed at the beginning of an instruction.

@ - Load Static: loads a type's static methods, fields and properties and gain implicit access to them. This will reset the instance to null. ex. @TypeName<int>
* - Load Instance: load an instance from any variable, method, field or property that you can access either implicitly, or by type/member/variable name. 
	Simply put, Load Instance assigns the return value of a field, property, method or variable as the currently loaded instance. ex. *Field or *Type.Method()
^ - Cast Instance: cast an instance to a base type, interface, or inheritor if possible. This changes the loaded type and implicitly available members to that of the casted type.
    ex. ^baseType 

+ - Add Variable: Add the current instance as a variable by name. You can load this variable by name using Load Instance. ex. +varName
- - Remove Variabie: Remove a variable by name. ex. -varName

~ - Chain Invoke: Chain multiple operations together, including operations with controllers. Each operation is delimited by a ; semicolon.
	Warning - This is done with a lot less poise than type argument and method parameter analysis.
    Your chain is split into multiple strings directly at it's semicolons - DO NOT use semicolons in char and string values, or they will be broken up and your
    invocation will throw an exception.


? - Query: Query the currently loaded type for member data. 


Chain Invocation Example:

~ *class.new(13, "Hello World"); BoolField = base.Evaluate(); +var_class; @someType; method(var_class.Method());

[1] Loading the current instance as an instance of type "Class", by calling a constructor
[2] Assigning a value to an instance field using a base method
[3] Adding the current instance as a variable
[4] Loading a type's static members
[5] Invoking a static method from that type, passing our variable, and invoking a method from the variable to be returned as our parameter value

When an enumerable value is returned as part of an invocation in a chain, it is not enumerated. It must be returned individually to be viewed.






Using the Navigator: Constructors/Overloads/Query

Method overloads are resolved with alternative names, due to lack of implicit overload resolution in the system.
Constructors are treated as overload methods named new. Constructors are called like static methods.
ie. Class<int>.new()

Overload keys are given a tag with a number. It will resemble this

key      value
Method:1 void Method()
Methox:2 void Method(int)

Use these custom keys to access specific overloads.
ie. method:2(22);

Overloaded generic methods will typically look like this:
key          value
Method:1<T> void Method<T>()
Method:2<T> void Method<T>(T)

Always make sure to put your :1 overload index BEFORE your generic arguments.

To view a type's resolved method names you can use our two query options:

Query:

The helper class "Types" provides multiple methods for querying type members.

Fields<T>(string,BindingFlags), Methods<T>(string,BindingFlags) and Props<T>(string)
with nongeneric alternatives
Fields(Type,string,BindingFlags), Methods(Type,string,BindingFlags), Props(Type,string)

ex. types.fields<int>("value", instance|public);

String and BindingFlags are optional values. The string is a "containing" value, the query will return members who's name contains that string (caseless)
if the value is not null.
The bindingflags are search options. Currently supported flags include:
Public
NonPublic
Static
Instance
DeclaredOnly
FlattenHierarchy
By default, all these flags are true.

Furthermore, you can use the ? controller to query the currently loaded type.
This follows the *exact* same parameter format and rules as the query methods in the Types class, but without type arguments.
The names are the same.
You can choose to query like a method, or query parameterlessly by name, using the default values.
Ie.
?methods
or
?fields(null, static|public|instance);

You can also use query to view your variables by typing ?vars






Using the Navigator: Helper Class - Types

The Navigator comes with a static helper class called Types. It provides various methods, including the previously
mentioned alternative/static query methods. Here is a list of Types' additional helper methods:

Of<T> and Of(string) - return a type object, either with a key matching the string, or typeof(T). String variant is mainly for obtaining generic definitions, ex. "List<T>" or "Dictionary<K,V>"
Struct<T>(T) - return an unmanaged struct == the parameter values
Enum<T>(T) - return an enum value == the parameter values
String(string) - return a string == the parameter values
Array<T>(params T[]) and Array<T>(int) - create an array using params, or create a presized array
LateCache overloads - Cache a specific type from an assembly by type name.

There are various other classes pre-cached which can be viewed in the TypeCache itself.




Using the Navigator: TypeCache

The navigator relies on the TypeCache to access any type. You can cache your types using the public CacheType and CacheTypes methods in TypeCache.
This is the simplest way to do it, here is an example of me caching only public types with a short name.

            Assembly xquinn = Assembly.Load("XQuinn");
            TypeCache.CacheTypes(xquinn.GetTypes().Where(x => x.IsPublic), false);

CacheTypes(IEnumerable<Type>,bool) by default returns a cache-compatible name for your type, either fullname, or shortname. You can read more about
how it gets type names below. There is an overload that takes an 'append' string. It will append this value to the beginning of every type name.
There is another overload that uses a delegate to allow you to input custom logic for returning string names from types. 
If you return a null key using this delegate, the paired type will be skipped and not cached.

If you are using your own custom cache names, it is recommended that you first use TypeCache.GetCompatibleName(Type,bool) before appending any
extra data to your customized name.
Reflection may mangle typenames - generics have extra data appended to their name, and nested types have a + instead of a member accessor operator.
GetCompatibleName snips off the extra generic data and replaces + with a member accessor operator.
ex. the nested generic type
NameSpace.TopType.NestedType<T>
will typically have a reflection name something like
Namespace.TopType+NestedType`[1]T
The method will convert it to the string
NameSpace.TopType.NestedType (see more below for why we dont include <T>)

Type names have specific rules:
You should follow the exact same naming rules for class names as you would in normal C#. 
If you are curious on the specific rules, check out TypeCache.ThrowIfBadKey(string).

Note: Do not attempt to create string keys such as "Class<T>" for generic definitions. These will be considered invalid and will throw.
The system internally handles the inclusion of generic parameters in type keys.
Furthermore, you should not attempt to cache concrete generic types, such as List<int>. The cache only accepts generic definitions.
Class<T> should be cached with string key "Class", it will not cause conflicts with a nongeneric Class of the same name, 
or other generic types with the same name and a different number of args.






Assignment Caveats
There are a few. 
Variables are immutable. They cannot be reassigned or overwritten. You must remove and readd them manually to update them.
If you load a field/property as the instance, and then reassign that field/property in it's declaring type, the current instance will not reflect changes, though
the changes will occur in the field itself. 
It is generally better to not try to assign to fields/properties that you currently are loaded into.
ex.
Class
{
    OtherClass Field;
}

If you load Field as the current instance, and then reassign Field ie. class.Field = OtherClass.new() , your currnet loaded instance
will lose reference equality with the actual field itself, you will need to reload class.Field;



Assigning to the members of struct fields currently does not work. The changes will not be reflected in the type that the struct field is declared in.
If you want to reassign a member of a struct field, you need to load the struct, reassign the value, then assign the struct to this
ex.

Class
{
    Struct Field;
}

Struct
{
    string InnerField;
}

Load Class.Field, then modify InnerField, then assign Class.Field to this.

example using a chain

~ *class.new(); +var_class; *Field; InnerField = "Hello World"; var_class.Field = this;
